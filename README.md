# 司南 · 多身份学习规划平台

> 一个带反馈回路的学习规划 Agent：**定目标 → 长线规划 → 每日作战清单 → 打卡/汇报 → 动态重规划**
>
> 支持身份切换（考研 / 专升本 / 教师），加身份只加文件，引擎一行不改。

---

## 一、这是什么

市面上多数"学习 AI"做的是**答疑**（这题怎么做）。司南做的是**取舍决策**（现在该学什么、学完没有、下一步改什么）。

四个核心场景：

| 场景 | 输入 | 输出 |
|---|---|---|
| 长线规划 | 目标院校 / 考试日期 / 每日时长 | 基础-强化-冲刺三阶段里程碑 |
| 每日规划 | 当前掌握度画像 | 按**提分性价比**排序的今日作战清单（含理由与验收标准） |
| 打卡 | 一键 | 连续打卡天数（**不触发重规划**） |
| 汇报 | 文字 + 照片双通道 | 掌握度更新 → 评估偏差 → **重写明日计划** |

## 三、架构：三层解耦

```
┌─ 身份包（roles/）· 可插拔策略 ──────────────────────┐
│   kaoyan（考研·数二，已落地）                        │
│   zhuanshengben（专升本，占位）  teacher（教师，占位）│
│   新增身份 = 新建一个文件 + 注册，引擎零改动          │
└───────────────────────┬────────────────────────────┘
                        │ 提供：目标模型 / 考点树 / 因子 / 权重 / 提示词
┌───────────────────────▼────────────────────────────┐
│  通用引擎（core/）· 与身份完全无关                   │
│   意图路由 → 规划器 → 优先度引擎 → 汇报解析          │
└───────────────────────┬────────────────────────────┘
                        │
┌───────────────────────▼────────────────────────────┐
│  数据底座（db/）· 全部带 user_id + role 维度         │
│   画像 / 考点树 / 计划 / 打卡·汇报 / 掌握度画像       │
└────────────────────────────────────────────────────┘
```

### 优先度引擎（项目灵魂）

```
priority = Σ wᵢ · fᵢ(ctx, kp)
```

因子与权重全部由身份包提供，引擎不感知具体身份：

| 身份 | 因子与权重 |
|---|---|
| 考研 | 考频 `+0.40` ｜ 掌握度缺口 `+0.35` ｜ 遗忘紧急度 `+0.15` ｜ 时间成本 `-0.10` |
| 教师 | 教学进度紧迫度 `+0.45` ｜ 学情反馈 `+0.25` ｜ 质量要求 `+0.10` ｜ 备课工作量 `-0.20` |

考研包还有**动态调权钩子**：剩余 ≤ 60 天时上调考频权重、放宽成本惩罚（冲刺期该啃硬骨头）。

## 六、核心设计决策

### 1. 打卡与汇报是两个功能，共用一张表

| | 打卡 | 汇报 |
|---|---|---|
| 回答 | **做没做**（二元） | **做得怎样**（有内容） |
| 成本 | 1 秒 | 30 秒 - 2 分钟 |
| 触发重规划 | **否** | **是** |

**打卡刻意不触发重规划**：打卡的信息量不足以支撑任务排序变化。若打卡就重排，用户会发现计划天天变，信任度会崩。

### 2. 汇报走对话而不是表单

汇报本质是对话：信息不足时要能追问"错了 3 道，是没思路还是算错了？"，表单做不到多轮澄清。同时复用现有 SSE + checkpointer + 多模态链路，零前端成本。

### 3. 计划稳定性保护（防震荡）

- **只改未来，不改今天**：汇报影响的是明天的计划，今天已发出的清单不推翻
- **小偏差不重排**：完成率偏差 ≤ 10% 时只写提醒，不调整任务顺序
- **顺延而非丢弃**：未完成项进入次日清单首位

### 4. 掌握度用指数平滑，且不设特例

```python
mastery_new = mastery_old + 0.3 × (accuracy - mastery_old)
```

首次出现的知识点以先验值 0.3 起步，走**完全相同**的公式。若直接以 accuracy 作初值，等于"做一次题就认定掌握度 60%"，会系统性高估。

真正生效的公式可以现场演示：一次证据只推动 30%，需要持续证据才改变画像。

### 5. 双轨记忆，职责分离

| 存储 | 作用 | 管理者 |
|---|---|---|
| `checkpoints` / `writes` | 会话内短期上下文 | LangGraph SqliteSaver |
| `mastery` 表 | 跨会话长期画像 | `db/repository.py` |

### 6. 双模型编排

主模型（deepseek）是纯文本的，不具备多模态能力。因此把视觉识别收敛成 `recognize_homework` 工具，只在需要时调用——既恢复多模态链路，又按需付费。

## 八、已知限制

- 专升本 / 教师为**占位实现**：有完整结构（目标模型、因子、提示词），考点树未按官方大纲深挖
- 不支持"没有明确考试日期"的自由学习者（长期规划会按 180 天兜底估算）
- 前端 `@` 提及用**后端意图路由**替代（原前端只有构建产物无源码，已重做为单文件 HTML，`@` 组件可后续补上）
- 汇报解析依赖模型判断，已通过提示词约束"有明确数量时不得追问"，但极端模糊输入仍可能反复追问
